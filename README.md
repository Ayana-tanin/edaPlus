# eda+

Telegram-бот и Mini App для продажи нераспроданной еды со скидкой: покупатель бронирует набор и забирает его сам, оплата при получении.

Один сервер обслуживает всё: API, бота и интерфейсы покупателя, партнёра и администратора (все три открываются внутри Telegram).

| Часть | Технологии |
|---|---|
| Сервер | Node.js 22, Express, SQLite (better-sqlite3) |
| Бот | grammY, long polling |
| Mini App | React, Vite |

## Запуск без Telegram

```bash
npm install
```

```bash
cp .env.example .env
```

В `.env` укажите `DEV_AUTH=true` и `ADMIN_TELEGRAM_IDS=9001`, затем:

```bash
npm run seed
```

```bash
npm run dev
```

Откройте http://localhost:5173. В разделе «Профиль» можно переключаться между покупателем, партнёром и админом. Уведомления в этом режиме пишутся в лог сервера.

## Запуск с настоящим ботом

1. Создайте бота у [@BotFather](https://t.me/BotFather) и запишите токен в `BOT_TOKEN`.
2. Получите HTTPS-адрес. Для локальной проверки подойдёт туннель:

   ```bash
   cloudflared tunnel --url http://localhost:5173
   ```

3. Запишите адрес в `WEBAPP_URL`, поставьте `DEV_AUTH=false` и запустите `npm run dev`.
4. Напишите боту `/id`, добавьте свой ID в `ADMIN_TELEGRAM_IDS` и перезапустите сервер.
5. Нажмите `/start` и кнопку «Открыть eda+».

## Роли

| Роль | Как назначается | Что может |
|---|---|---|
| Главный админ | Telegram ID в `ADMIN_TELEGRAM_IDS`, после правки нужен перезапуск | Всё: кафе, админы кафе, пользователи, любые блюда и заказы |
| Админ кафе | Главный админ добавляет его в разделе «Заведения» по Telegram ID (бот покажет его по команде `/id`) или по @username того, кто уже запускал бота | Только в своём кафе: блюда, архив, заказы и их статусы, выдача по коду |

Блюдо из архива не показывается гостям и не бронируется. В архив также попадают блюда с прошедшим периодом получения: чтобы вернуть такое блюдо, укажите новую дату.

## Production

Пошаговая установка на бесплатный сервер Oracle Cloud: [DEPLOY-ORACLE.md](DEPLOY-ORACLE.md).

```bash
docker compose up -d --build
```

Compose запускает приложение и Caddy, который выдаёт HTTPS для `DOMAIN` из `.env`. База и фото лежат в томе `eda-data`; копию делает `scripts/backup.sh`. Запускайте один экземпляр: SQLite и long polling не рассчитаны на несколько.

## Правила, которых нет в ТЗ явно

- **Статус «Не получен».** Нужен для истории заказов (FR-07). Ставится автоматически через `NO_SHOW_GRACE_MINUTES` после конца периода получения. Остаток при этом не возвращается.
- **Время получения в заказе** с несколькими позициями: пересечение их периодов. Если пересечения нет, заказ не создаётся и покупателю предлагается оформить позиции отдельно.
- **Отмена.** Покупатель может отменить только активный заказ, остаток возвращается. Админ кафе и главный админ могут поставить любой статус, все изменения попадают в историю. Отмена уже выданного заказа остаток не возвращает.
- **Категория** добавлена в форму партнёра: она нужна для главной страницы (FR-02).
- **Период получения** укладывается в один день, переход через полночь пока не поддерживается.
- **Время** хранится как местное время `APP_TIMEZONE`. Для работы в нескольких часовых поясах пояс нужно будет перенести в заведение.
